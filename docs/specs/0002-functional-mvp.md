# 0002 — Game Lab Functional MVP

- **状态**：Accepted
- **负责人**：Product / PM
- **创建日期**：2026-10-02
- **关联页面**：`lab.html`
- **前置规格**：`docs/specs/0001-game-ideation-lab.md`

## 1. MVP 目标

验证 Game Lab 的核心工作流是否可以在无后端条件下跑通：

```text
输入口碑样本
→ 动机与缺口分析
→ 生成机制假设
→ 生成实验方案
→ 游玩最小机制原型
→ 采集行为事件
→ 输出实验结果
→ 导入 / 导出数据
→ 沉淀机制知识
```

本 MVP 的目标不是证明商业可行性，而是验证：

> 用户是否能完成一次从“口碑洞察”到“机制实验结果”的完整闭环。

## 2. 范围

### 2.1 P0 功能

1. **口碑输入**
   - 支持载入演示数据；
   - 支持粘贴 JSON 数组；
   - 支持按行输入 `游戏|情绪|评论`。

2. **动机与缺口分析**
   - 基于关键词规则识别玩家动机；
   - 统计动机强度、负面比例、跨竞品出现次数；
   - 输出可解释的证据列表。

3. **机制假设生成**
   - 根据动机缺口生成机制假设；
   - 每个假设包含目标玩家、机制组合、差异点、先例、风险、证据；
   - 置信度由缺口强度、证据数量和跨竞品次数计算。

4. **实验设计**
   - 自动生成对照组与实验组；
   - 定义完成率、重开率、主动调整率、分享意愿等指标；
   - 明确最低通过线。

5. **可玩机制原型**
   - 浏览器内可玩；
   - 对照组为手动采集；
   - 实验组为生物捕捉、岗位分配与自动化生产；
   - 目标是验证“生物作为生产单元”的机制假设。

6. **行为事件采集**
   - 采集 `start`、`tutorial_complete`、`capture`、`assign`、`cycle`、`complete`、`restart`、`share_intent`、`abandon` 等事件；
   - 事件写入浏览器 `localStorage`；
   - 支持查看事件流。

7. **实验结果**
   - 按对照组 / 实验组计算完成率、重开率、分享率、主动调整率；
   - 输出行为漏斗与结论建议；
   - 明确提示小样本结果不可直接用于立项决策。

8. **数据管理**
   - 导出完整实验 JSON；
   - 导出事件 CSV；
   - 导入 JSON 恢复数据；
   - 清空本地实验数据。

9. **机制知识库**
   - 根据实验结果生成机制知识；
   - 记录机制、动机、效果、边界条件与下一步。

### 2.2 非目标

1. 真实评论抓取；
2. 后端服务与账号系统；
3. 大模型调用；
4. 多人联机原型；
5. 商业化支付；
6. 统计显著性检验；
7. 自动生成完整商业游戏。

## 4. 关键交互

### 4.1 输入洞察

1. 用户载入演示数据或粘贴自己的评论样本；
2. 系统解析输入并执行规则引擎；
3. 输出动机强度、缺口排序和证据。

### 4.2 机制假设

1. 系统根据最高缺口生成最多 3 个假设；
2. 用户查看假设的机制组合、证据和风险；
3. 用户选择一个假设进入实验。

### 4.3 原型实验

1. 用户选择对照组或实验组；
2. 系统生成本地可玩机制切片；
3. 玩家行为被记录为事件；
4. 完成或放弃后结束会话。

### 4.4 结果回流

1. 系统读取本地会话数据；
2. 输出两组指标和行为漏斗；
3. 给出保留、修改、继续验证的机制方向。

## 5. 验收标准

1. 载入演示数据后能生成动机与缺口分析；
2. 至少生成一个带证据链的机制假设；
3. 对照组和实验组均可完成一次可玩流程；
4. 每次游玩都会写入本地事件；
5. 结果页能计算完成率、重开率、分享率与主动调整率；
6. 支持 JSON 导出、导入和事件 CSV 导出；
7. `npm test` 通过；
8. HTML 与 JavaScript 语法检查通过。

## 6. 验证边界

- 本 MVP 的行为数据来自本地浏览器，不等价于真实玩家样本；
- 小样本实验只用于演示和流程验证；
- 结果页必须提示“不能直接用于立项决策”；
- 机制知识库当前由规则生成，不代表经过统计验证的结论。
